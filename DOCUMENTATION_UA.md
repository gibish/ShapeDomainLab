# Документація ShapeDomainLab

## 1. Призначення та сфера застосування

**ShapeDomainLab** — настільна та командно-рядкова програма Python для відтворюваного формування, документування, аудиту та експериментального використання контрольованих синтетичних доменів простих геометричних фігур. Програма підтримує дослідження в комп'ютерному зорі, машинному навчанні, класифікації зображень, сегментації та оцінюванні стійкості моделей за явно заданих і контрольованих умов візуалізації.

Програма створює зображення класів `circle`, `octagon`, `rectangle`, `square` і `triangle`. Вона не є засобом моделювання природних сцен: її коректна наукова роль полягає у вивченні алгоритмів у середовищі, де джерела варіації задані явно та можуть бути ізольовані.

Результатом роботи є набір даних із незалежними підмножинами навчання, валідації та тестування, супровідними метаданими, звітом контролю якості та криптографічним маніфестом цілісності. Додатково програма містить відтворюваний конвеєр навчання класифікаторів PyTorch і набір контрольних конфігурацій для дослідів на стійкість.

## 2. Функціональні можливості

Програма забезпечує:

- генерацію зображень у градаціях сірого або RGB;
- формування класово-структурованих підмножин `train`, `val` і `test`, сумісних із `torchvision.datasets.ImageFolder`;
- параметричне варіювання повороту, масштабу, положення, товщини контуру, кольору/інтенсивності, режиму заливки, шуму та обрізання краєм кадру;
- збереження необов'язкових бінарних масок сегментації;
- збереження для кожного зразка мітки, незалежного зерна генератора та фактичних параметрів рендерингу;
- валідацію структури, форматів, метаданих, масок і можливих дублікатів;
- створення аналітичного звіту з описовими статистиками, діагностикою потенційних конфаундерів та рисунками;
- запуск через графічний інтерфейс або CLI;
- навчання `tiny_cnn` чи `resnet18`, оцінювання на тестових доменах і агрегацію метрик.

## 3. Встановлення та запуск

Потрібен Python 3.10 або новіший. У корені проєкту створіть ізольоване середовище та встановіть базові залежності:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Для аналізу наборів даних встановіть додаткові залежності:

```powershell
pip install -r requirements-analysis.txt
```

Для навчання моделей встановіть експериментальні залежності:

```powershell
pip install -r requirements-experiments.txt
```

Найпростіша генерація виконується командою `python main.py`. Графічний інтерфейс запускається командою:

```powershell
python -m src.gui.app
```

Пакет також можна інсталювати через `pip install .`; після цього доступна команда `shape-domain-lab`.

## 4. Швидкий початок у командному рядку

Наведена команда створює 100 навчальних, 20 валідаційних і 20 тестових зображень **кожного** з п'яти класів, з фіксованим зерном випадковості:

```powershell
python main.py --output datasets/demo --train-count 100 --val-count 20 --test-count 20 --seed 42
```

Щоб згенерувати маски сегментації, додайте `--save-masks`:

```powershell
python main.py --output datasets/segmentation-demo --train-count 100 --val-count 20 --test-count 20 --save-masks --seed 42
```

Режим загальної кількості зображень розподіляє задане число між підмножинами за схемою `70/15/15` або `80/10/10`:

```powershell
python main.py --output datasets/demo-total --dataset-count 1000 --split-ratio 70/15/15 --seed 42
```

Якщо загальна кількість не ділиться порівну на число класів, програма розподіляє залишок між класами по одному зразку; підсумок кожної підмножини зберігається точним. Перед повною генерацією можна оцінити очікуваний розмір:

```powershell
python main.py --output datasets/demo --train-count 100 --val-count 20 --test-count 20 --estimate
```

## 5. Параметри генерації та їх наукова інтерпретація

| Група | Параметри CLI | Інтерпретація |
|---|---|---|
| Дані | `--output`, `--image-size`, `--format`, `--classes` | Місце збереження, роздільність, формат (`png`, `jpg`, `gif`) і склад класів. |
| Поділ | `--train-count`, `--val-count`, `--test-count` | Кількість зразків на клас у ручному режимі. `val` призначена лише для вибору моделі та гіперпараметрів. |
| Відтворюваність | `--seed` | Глобальне зерно. Для кожного зразка детерміновано обчислюється незалежне зерно, що записується в метадані. |
| Колір | `--color-mode`, `--background-color`, `--foreground-color` | Режим `grayscale` або `rgb`; у RGB кольори задаються трійками 0–255. |
| Геометрія | `--rotation-min/max`, `--scale-min/max`, `--center-offset-min/max` | Фактори інваріантності до повороту, масштабу та зміщення. Кути вимірюються в градусах, зміщення — у пікселях. |
| Вигляд | `--fill-mode`, `--noise-level` | Режими `outline`, `filled`, `outline_fill`; однорідний фоновий шум. |
| Край кадру | `--edge-clipping`, `--min-visible-ratio` | Дозволяє часткове обрізання однією межею кадру; частка видимості обмежена інтервалом 0,6–1,0. |
| Сегментація | `--save-masks` | Формує маску PNG у режимі `L`: 0 — фон, 255 — фігура, включно з контуром у відповідних режимах заливки. |

Приклад контрольованого домену зі змінним поворотом і незмінними іншими умовами:

```powershell
python main.py --output datasets/rotation --train-count 1000 --val-count 200 --test-count 500 --image-size 64 --format png --fill-mode outline_fill --rotation-min -45 --rotation-max 45 --scale-min 1 --scale-max 1 --center-offset-min 0 --center-offset-max 0 --noise-level 0 --seed 20260727 --save-masks
```

Для дослідження причинного впливу певного фактора слід змінювати лише цей фактор, фіксуючи всі інші параметри, склад класів, кількість прикладів та протокол навчання.

## 6. Графічний інтерфейс

GUI забезпечує вибір усіх основних параметрів, класів, каталогу виведення та формату. Панель попереднього перегляду дозволяє перевірити поточну конфігурацію без створення повного набору. Генерація виконується фоновим робітником, тому інтерфейс не блокується.

Основний робочий порядок: (1) задати кількість і поділ даних; (2) вибрати параметри рендерингу; (3) натиснути **Preview**; (4) за потреби використати **Estimate**; (5) зберегти конфігурацію через **Save Config**; (6) виконати **Generate**; (7) перевірити повідомлення якості та повний журнал. Кнопки **Summary** і **Open Summary** відображають структуру існуючого набору. **Load Config** застосовує лише валідний JSON-конфіг; **Clear Dataset** вимагає підтвердження і очищує тільки каталог, розпізнаний як згенерований набір.

Якщо каталог виведення не порожній, програма перезаписує його лише тоді, коли це вже валідний набір ShapeDomainLab і користувач підтвердив операцію. Неструктурований непорожній каталог відхиляється без видалення файлів.

## 7. Структура та супровідні артефакти набору даних

```text
dataset/
  train/<class>/
  val/<class>/
  test/<class>/
  masks/<subset>/<class>/        # необов'язково
  metadata.csv
  class_mapping.json
  generation_config.json
  dataset_manifest.json
  quality_report.json
  quality_report.md
  log.txt
  README.md
```

`metadata.csv` має версію схеми 2.1. Один рядок описує один зразок: відносний шлях, підмножину, клас і його числовий ідентифікатор, незалежне зерно, версії програми/Python/NumPy/Pillow, параметри рендерингу, геометричні величини, координати центра, межі фігури та ознаки обрізання. Поля `shape_width`, `shape_height` і `shape_area` описують геометричний примітив до растеризації; це не площа ненульових пікселів. Межі `bbox_*` задані після повороту та розміщення, але до обрізання межами кадру.

`generation_config.json` є машинно-читаним описом умов генерації. `class_mapping.json` фіксує відповідність класів і числових ідентифікаторів. `dataset_manifest.json` містить SHA-256 хеші й розміри файлів, тому дає змогу перевірити незмінність набору. Ці файли необхідно архівувати разом із результатами дослідження.

## 8. Контроль якості, аналіз і обмеження інтерпретації

Після генерації запускається контроль якості. Він перевіряє структуру директорій, кількість файлів, роздільність, фактичний закодований формат і колірний режим зображень, метадані, мапу класів і службові файли. Для масок додатково контролюються структура, кількість, PNG-формат, режим `L`, розмір, бінарні значення пікселів і відповідність шляхам у метаданих.

Під час генерації програма не допускає точних дублікатів у межах одного набору: вона порівнює SHA-256 закодованого зображення з раніше створеними файлами та, у разі збігу, детерміновано повторює рендеринг з похідним seed. Якщо після 100 спроб унікальний зразок не отримано, генерація зупиняється з помилкою; у такому разі слід збільшити допустиму варіативність або зменшити розмір набору. Звіт також виявляє кандидати на близькі дублікати за середнім хешем. Близькі дублікати — лише попередження для ручної перевірки, а не доказ семантичної тотожності. Перед навчанням переконайтеся, що `quality_report.json` має статус `passed`, а маніфест є валідним.

Для описового аналізу виконайте:

```powershell
python main.py --analyze datasets/benchmarks/clean
```

Команда записує `analysis/analysis_report.json`, `analysis/analysis_report.md` і рисунки розподілів параметрів, монтаж репрезентативних зразків та приклади екстремальних значень. Попередження про конфаундери означають, що середні параметри можуть відрізнятися між класами. Це діагностичний сигнал, а не статистичний тест і не доказ причинного ефекту.

## 9. Відтворюваний науковий експеримент

### 9.1. Формулювання задачі

Приклад дослідницького питання: *як поворот, геометричне зміщення, шум і часткове обрізання впливають на здатність класифікатора розпізнавати прості геометричні фігури, якщо навчання виконано на чистому домені?*

Нульова гіпотеза: контрольовані зсуви домену не змінюють очікувані `accuracy`, збалансовану точність або macro-F1. Альтернативна гіпотеза: принаймні один фактор знижує щонайменше одну з цих метрик. Незалежна змінна — домен генерації; залежні змінні — метрики тестування. Контрольовані змінні включають набір класів, розмір зображень, розмір вибірки, архітектуру, процедуру оптимізації та, для порівнюваних умов, конфігурацію набору даних.

### 9.2. Готові домени

У `experiments/configs` наявні шість версіонованих конфігурацій: `clean`, `rotation`, `geometry`, `noise`, `clipping`, `composite`. Вони використовують п'ять класів, 64×64 пікселі, відтінки сірого, PNG, маски та по 1000/200/500 прикладів на клас для train/val/test. Кожний домен змінює лише названий фактор, окрім `composite`, де поєднано всі зсуви.

```powershell
python main.py --config experiments/configs/clean.json
python main.py --config experiments/configs/rotation.json
python main.py --config experiments/configs/geometry.json
python main.py --config experiments/configs/noise.json
python main.py --config experiments/configs/clipping.json
python main.py --config experiments/configs/composite.json
```

Для попарного порівняння, де потрібні однакові базові зразки у різних доменах, створіть копії конфігурацій з навмисно однаковим `seed` і зафіксуйте це рішення у протоколі. Інакше різні зерна конфігурацій забезпечують незалежно відтворювані домени.

### 9.3. Навчання, тестування та статистичний план

Спочатку навчайте модель лише на `clean/train`. `clean/val` дозволено застосовувати для вибору архітектури, епох та гіперпараметрів. Після фіксації цих рішень виконайте рівно одне фінальне оцінювання обраної моделі на `clean/test` і на `test` кожного зсувного домену. Не використовуйте тестові метрики для підбору моделі.

```powershell
python -m experiments.train --dataset datasets/benchmarks/clean --output runs/clean-seed-1 --model tiny_cnn --seed 1
python -m experiments.evaluate --dataset datasets/benchmarks/clean --run runs/clean-seed-1 --name clean
python -m experiments.evaluate --dataset datasets/benchmarks/rotation --run runs/clean-seed-1 --name rotation
python -m experiments.evaluate --dataset datasets/benchmarks/geometry --run runs/clean-seed-1 --name geometry
python -m experiments.evaluate --dataset datasets/benchmarks/noise --run runs/clean-seed-1 --name noise
python -m experiments.evaluate --dataset datasets/benchmarks/clipping --run runs/clean-seed-1 --name clipping
python -m experiments.evaluate --dataset datasets/benchmarks/composite --run runs/clean-seed-1 --name composite
```

Повторіть кожну умову з кількома незалежними зернами моделі, наприклад 1, 2, 3, 4 і 5, не змінюючи конфігурацію даних у межах порівняння. Для кожного домену подайте середнє та стандартне відхилення `accuracy`, balanced accuracy і macro-F1; також подайте показники за класами. Для статистичного висновку доцільно наперед визначити тест для порівняння повторів (наприклад, парний тест за однакових зерен, якщо припущення виконані) та рівень значущості. Разом із p-значенням слід подати розмір ефекту й інтервал невизначеності; вибір тесту, число повторів і правило обробки множинних порівнянь мають бути зафіксовані до аналізу.

Агрегуйте отримані метрики:

```powershell
python -m experiments.aggregate_results --runs runs --output results/benchmark-results
```

Створюються `benchmark-results.csv` і `benchmark-results.md`. Перевірка матриць помилок або клас-специфічних відмов виконується за CSV прогнозів, записаними для кожного оціненого домену.

### 9.4. Мінімальний набір матеріалів для статті

У розділі «Матеріали і методи» зазначте: версію програми та Git-ревізію; операційну систему й версії Python, NumPy, Pillow, PyTorch і torchvision; усі JSON-конфігурації; зерна наборів даних і моделей; склад класів; розмір зображень; поділ train/val/test; діапазони факторів; архітектуру; оптимізатор, швидкість навчання, розмір пакета, число епох і пристрій обчислень.

До репозитарію даних або додатків статті додайте `generation_config.json`, `metadata.csv`, `dataset_manifest.json`, `quality_report.json`, аналіз набору, `run_config.json`, `history.json`, усі `metrics-*.json` та `predictions-*.csv`. У тексті статті чітко відокремлюйте результат на синтетичному контрольованому домені від тверджень про узагальнення на реальні зображення.

## 10. Відтворюваність і відомі межі

Фіксоване зерно робить генерацію даних детермінованою за незмінних версій програмного середовища; метадані містять незалежне зерно кожного зразка. Конвеєр PyTorch встановлює зерна Python, NumPy і PyTorch та вмикає детермінований режим cuDNN. Проте бітова тотожність навчання може залежати від версії PyTorch, ОС, обладнання й пристрою. Для найсильнішої заяви про відтворюваність відтворюйте зафіксоване середовище та, за потреби, виконуйте розрахунки на CPU або еквівалентному прискорювачі.

Синтетична простота є як перевагою, так і обмеженням: вона полегшує ізоляцію факторів, але не відтворює текстури, освітлення, оклюзії, складний фон і семантичну різноманітність реальних даних. Висновки про механізми стійкості моделі в цьому середовищі науково коректні; переносити їх без додаткової перевірки на природні дані не слід.
